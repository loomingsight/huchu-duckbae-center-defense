# 후추 생존형 수동 전투 전환 설계

- 상태: 승인됨
- 승인일: 2026-07-22
- 백로그: `HD-BL-014`

## 1. 배경

현재 게임은 맵 중앙의 보호소를 적의 이동·공격·투사체·피해·패배 판정 기준으로 사용한다. 후추와 덕배는 보호소를 지키는 공격 주체이며 후추의 짖기와 습득 기술은 자동으로 시전된다.

게임의 중심을 보호소 방어에서 후추와 덕배의 생존으로 전환한다. 후추는 플레이어가 이동과 기술 시전을 직접 조작하는 유일한 피격 대상이며, 덕배는 후추를 따라다니면서 자동 공격하는 영구 컴패니언으로 유지한다.

## 2. 목표

- 보호소의 게임플레이·렌더링·HUD·문구·에셋 파이프라인 의존성을 제거한다.
- 후추에게 독립 HP를 부여하고 후추의 생존 여부로 승패를 판정한다.
- 덕배를 피격되지 않는 영구 동행·자동 공격 컴패니언으로 명확히 정의한다.
- 후추의 짖기와 세 습득 기술을 왼손 버튼으로 수동 시전하게 한다.
- 기존 자동 조준 규칙을 유지해 모바일에서 이동과 공격을 동시에 조작할 수 있게 한다.
- 후추 위치 변화에 맞춰 적 전체의 이동 경로를 지속적으로 다시 계산한다.
- 적 최대 60마리에서도 공용 경로장을 사용해 모바일 성능을 보호한다.

## 3. 비목표

- 수동 방향 조준, 드래그 범위 지정 또는 조준 스틱을 추가하지 않는다.
- 덕배에게 HP, 피격 판정, 사망 또는 부활 규칙을 추가하지 않는다.
- 신규 스테이지, 신규 적, 신규 기술 또는 장비 시스템을 추가하지 않는다.
- 최초 전환에서는 적 HP·공격력·공격 주기와 후추 기술 피해량을 재조정하지 않는다.
- 기술 습득을 위해 게임을 일시 정지하거나 별도 선택 창을 열지 않는다.

## 4. 확정 게임 규칙

### 4.1 후추와 덕배

- 후추의 최대 HP는 기존 보호소 난이도 기준을 이어받아 `1,000`으로 시작한다.
- 후추만 적의 이동·조준·공격·투사체 충돌 대상이 된다.
- 후추 HP가 0이 되는 고정 프레임에 패배를 확정한다.
- 덕배는 후추를 계속 따라다니며 현재 자동 공격 주기와 피해량을 유지한다.
- 덕배는 적의 표적이 되지 않고 피해 이벤트도 받지 않는다.
- 후추와 덕배의 화면상 동행 간격과 공격 애니메이션은 기존 컴패니언 연출을 유지한다.

### 4.2 승패

- 5웨이브의 예약 적과 활성 적을 모두 제거했고 후추 HP가 1 이상이면 승리한다.
- 마지막 적 처치와 후추 HP 0이 같은 고정 프레임에 발생하면 패배를 우선한다.
- 웨이브 종료·승리 오버레이는 기존 `WaveEndPresentationGate` 순서를 유지해 적 사망, 피해량 숫자와 간식 비행 효과가 끝난 뒤 표시한다.
- 패배는 후추의 마지막 피격과 쓰러짐 연출을 보여준 뒤 기존 1,200ms 결과 전환 규칙을 적용한다.

### 4.3 결과 문구

- 시작 버튼: `함께 출발하기`
- 승리 문구: `후추와 덕배가 끝까지 살아남았어요!`
- 패배 문구: `후추가 쓰러졌어요`
- 재시작 버튼: `다시 도전하기`

## 5. 상태와 이벤트 구조

### 5.1 후추 생명력

보호소의 생명력 책임을 `PlayerHealthSystem`으로 대체한다. 이 시스템은 최대 HP, 현재 HP, 피해 적용과 초기화를 전담한다.

`RunSnapshot`은 `shelterHp`와 `shelterMaxHp` 대신 다음 값을 제공한다.

- `playerHp`
- `playerMaxHp`
- 후추의 현재 충돌 중심과 피격 반경

`shelterDamageRequested`와 `shelterDamaged`는 각각 후추를 대상으로 하는 명시적인 피해 요청과 `playerDamaged` 이벤트로 교체한다. 피해 이벤트에는 실제 적용 피해량, 남은 HP, 피격 위치, 방향과 강도를 포함한다.

### 5.2 수동 행동 입력

DOM 버튼은 세션을 직접 수정하지 않고 `PlayerActionCommand`를 한 번만 큐에 넣는다. 세션은 다음 고정 프레임에 명령을 소비한다.

명령은 다음 조건을 모두 만족할 때만 시전을 시작한다.

- 게임 모드가 `playing`이다.
- 해당 기술을 습득했다. 짖기는 항상 습득 상태다.
- 기술이 쿨타임 또는 시전 중이 아니다.
- 기술별 유효 대상이 하나 이상 존재한다.
- 200ms 전역 시전 잠금이 끝났다.

거부된 명령은 피해·쿨타임·시전 애니메이션을 만들지 않는다. 유효 대상이 없을 때만 `대상이 없어요` 토스트를 짧게 표시한다. 같은 포인터 입력이 기술 습득과 시전을 동시에 일으키지 않게 한다.

## 6. 동적 경로 재계산

### 6.1 공용 경로장

현재 540×960 논리 맵을 30×30 논리 픽셀 셀로 나눈 18×32 저해상도 내비게이션 격자를 사용한다. 기존 여섯 오솔길의 선분 주변을 이동 통로로 표시하고 중앙 합류 영역을 서로 연결한다.

후추가 다음 중 하나를 만족하면 후추 셀을 시작점으로 역방향 최단 경로장을 다시 계산한다.

- 이전 계산 이후 다른 내비게이션 셀로 이동했다.
- 이전 계산 위치에서 15 논리 픽셀 이상 이동했고 마지막 계산 후 200ms 이상 지났다.

계산 빈도는 최대 초당 5회다. 상하좌우와 대각선을 포함한 8방향 이웃을 사용하고 대각선 비용은 `sqrt(2)`로 계산한다. 하나의 역방향 Dijkstra 결과를 모든 활성 적이 공유하며, 적마다 A*를 실행하지 않는다. 동일 비용 경로는 셀 좌표 순서로 결정해 같은 시드와 입력에서 결과가 재현되도록 한다.

### 6.2 경로 이탈과 실패 처리

- 후추가 통로 밖에 있으면 후추 셀을 가장 가까운 이동 가능 셀에 임시 연결한다.
- 적은 공용 경로장의 다음 셀을 향해 이동하고 마지막 연결 구간에서 후추에게 접근한다.
- 경로를 찾지 못하면 적이 멈추지 않도록 후추를 향한 직접 이동을 안전한 폴백으로 사용한다.
- 후추가 이동해 경로가 바뀌어도 적 위치는 순간 이동하지 않고 다음 고정 프레임부터 진행 방향만 부드럽게 바꾼다.
- 개장수의 트럭은 개장수의 실제 이동 궤적을 시간 지연해 따라가며 경로 전환 시에도 대각선 뒤 간격을 유지한다.
- 보스의 12시 방향 출현 규칙과 출현 진동은 유지한다.

## 7. 적 공격과 회피

- 모든 적은 후추만 추적하고 공격한다.
- 근접 공격은 타격 프레임에 후추가 사거리 안에 있을 때만 피해를 준다. 후추가 벗어나면 공격 애니메이션은 끝나지만 피해는 발생하지 않는다.
- 원거리 공격은 발사 순간의 후추 위치를 향해 투사체를 발사한다.
- 투사체는 이동 중인 후추의 현재 피격 원과 실제 교차할 때만 피해를 준다. 후추가 이동하면 투사체를 피할 수 있다.
- 똥 방치 보호자의 단거리 똥 던지기, 보스별 공격 종류·피해량·공격 주기는 유지한다.
- 꼬리치기 넉백 기준점은 삭제되는 보호소 중앙이 아니라 시전 순간 후추 위치로 바꾼다.

## 8. 후추 수동 기술

### 8.1 시전과 자동 조준

- `짖기`: 버튼 입력 시 가장 가까운 위협을 방향 기준으로 잠그고 기존 부채꼴 안의 모든 적을 타격한다.
- `꼬리치기`: 버튼 입력 시 후추 주변 기존 범위 안의 모든 적을 타격한다.
- `아쿠아빔`: 버튼 입력 시 기존 규칙대로 HP가 가장 높은 유효 적을 자동 선택한다.
- `안전신문고`: 버튼 입력 시 현재 활성 상태인 맵 전체 적을 대상으로 스냅샷을 만든다.
- 대상이 없으면 시전하지 않고 쿨타임도 시작하지 않는다.
- 시전이 수락된 순간에만 기술별 쿨타임을 시작한다.
- 기존 피해량, 범위, 타격 프레임, 효과와 기술별 정상 쿨타임은 유지한다.

### 8.2 습득

- 짖기는 게임 시작부터 사용할 수 있다.
- 꼬리치기·아쿠아빔·안전신문고는 기존 간식 비용과 습득 순서를 유지한다.
- 동일 버튼이 미습득 상태에서는 비용과 잠금을 표시하고, 간식이 충분하면 강조된다.
- 강조된 버튼을 누르면 기술만 습득하고 시전하지 않는다.
- 습득 직후 첫 쿨타임은 기존 규칙대로 정확히 1,000ms다.
- 게임은 기술 습득 중에도 멈추지 않는다.

## 9. 모바일 HUD

### 9.1 왼손 전투 버튼

- 왼쪽 아래 안전 영역 안에 56×56 CSS 픽셀 원형 버튼 네 개를 2×2로 배치한다.
- 윗줄은 `짖기`, `꼬리치기`, 아랫줄은 `아쿠아빔`, `안전신문고` 순서다.
- 각 버튼은 단색 아이콘과 짧은 한글 이름을 함께 표시한다.
- 보유 간식은 버튼 묶음 바로 위에 표시한다.
- 오른쪽 112×112 조이스틱과 전투 버튼의 터치 영역은 겹치지 않는다.
- 390×844 iPhone 기준으로 safe-area를 포함해 캔버스와 결과 오버레이를 가리지 않는다.

### 9.2 쿨타임 시계

- 시전 중이거나 쿨타임인 버튼은 실제 `disabled` 상태로 입력을 차단한다.
- 반투명 어두운 시계형 부채꼴이 버튼을 덮고, 남은 비율에 따라 시계 방향으로 걷힌다.
- 버튼 중앙에는 남은 시간을 올림한 초 단위 숫자를 표시한다.
- 준비되면 어두운 덮개와 숫자를 제거하고 테두리를 짧게 강조한다.
- `prefers-reduced-motion`에서는 강조 애니메이션 없이 색과 테두리만 바꾼다.
- 접근성 이름은 기술명, 잠금·비용·쿨타임·준비 상태를 포함한다.

### 9.3 상태 표시

- 기존 좌상단 자동 기술 목록에서 후추의 네 기술을 제거한다.
- 덕배의 자동 공격 상태만 작은 `덕배·자동` 행으로 유지한다.
- 후추 HP 바는 후추 발밑에 항상 표시하며 HP 비율에 따라 초록·노랑·빨강으로 바뀐다.
- 적에게 받은 피해량 숫자는 후추 위에 표시하고 강한 공격일수록 기존 규칙대로 더 크게 표시한다.

## 10. 보호소 제거 범위

다음 보호소 전용 요소를 런타임 계약에서 제거한다.

- `ShelterSystem`, `ShelterView`, `ShelterHpView`
- 보호소 스프라이트 생성·프리로드·렌더링·피격·실패 연출
- `BALANCE.shelter`와 보호소 중심·반경에 의존하는 전투 계산
- 보호소 HP 스냅샷, 이벤트, HUD와 결과 문구
- 보호소 런타임 에셋과 에셋 검증·리뷰 파이프라인의 필수 항목
- 보호소 전용 E2E 시나리오와 테스트 픽스처

과거 완료 백로그의 보호소 관련 구현 근거는 당시 상태 기록이므로 수정하지 않는다. 새 설계가 앞으로의 런타임 규칙을 대체한다.

## 11. 프레임 처리 순서

한 고정 프레임의 논리 순서는 다음과 같다.

1. 후추 이동 입력을 적용한다.
2. 필요하면 공용 경로장을 다시 계산한다.
3. 적을 이동하고 공격 상태를 갱신한다.
4. 수동 기술 명령과 덕배 자동 공격을 처리한다.
5. 적과 후추에게 피해를 적용한다.
6. 패배 우선 규칙으로 승패를 판정한다.
7. 논리 이벤트를 렌더링·사운드·HUD에 전달한다.

이 순서로 같은 프레임의 이동 회피, 공격과 사망 결과를 결정적으로 처리한다.

## 12. 구현 경계

구현은 하나의 에픽 안에서 다음 순서로 분리한다.

1. 보호소를 후추 HP와 생존 승패 모델로 교체한다.
2. 공용 동적 경로장과 후추 대상 적 공격·투사체 충돌을 적용한다.
3. 자동 기술을 명령 기반 수동 기술로 교체한다.
4. 왼손 전투 버튼, 쿨타임 시계, 후추 HP·피격 연출과 문구를 적용한다.
5. 보호소 에셋·파이프라인·테스트 계약을 제거하고 전체 회귀를 정리한다.

각 단계는 순수 규칙 계층과 Phaser/DOM 프레젠테이션 계층을 분리해 단위 테스트가 가능해야 한다.

## 13. 검증 기준

- 후추 HP의 피해·0 경계·초기화·동시 승패 우선순위를 단위 테스트로 고정한다.
- 덕배가 피해 대상이나 패배 조건에 포함되지 않음을 고정한다.
- 경로장 재계산 조건, 최대 5Hz, 결정적 경로, 경로 없음 폴백과 60적 공유를 고정한다.
- 움직이는 후추의 근접 회피와 원거리 투사체 충돌·빗나감을 고정한다.
- 네 기술의 수동 입력, 자동 조준, 대상 없음, 중복 탭, 전역 잠금과 쿨타임 경계를 고정한다.
- 동일 버튼의 잠금·구매·첫 1초·준비·시전 상태 전이를 고정한다.
- 쿨타임 시계 비율, 남은 초, disabled와 접근성 이름을 DOM 단위 테스트로 고정한다.
- 보호소 식별자와 런타임·에셋 파이프라인 의존성이 남지 않았는지 정적 회귀 테스트로 확인한다.
- 구현 완료 시 단위 테스트, 타입 검사, 프로덕션 빌드와 `git diff --check`를 실행한다.
- 사용자 소유 시각 스냅샷 두 개는 별도 승인 없이 변경하거나 커밋하지 않으며 E2E는 별도 요청 전까지 실행하지 않는다.
