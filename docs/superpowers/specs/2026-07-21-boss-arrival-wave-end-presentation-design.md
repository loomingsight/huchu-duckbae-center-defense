# 보스 출현과 웨이브 종료 연출 설계

작성일: 2026-07-21

## 목표

- 일반 적을 모두 처치한 뒤 보스를 기다리는 공백과 개장수 본체의 화면 밖 대기를 제거한다.
- 보스 생성 프레임에 짧은 화면 진동을 한 번 재생한다.
- 보스 속도를 최초 밸런스보다 총 40% 빠르게 맞춘다.
- 마지막 적의 사망·피해량·간식 연출이 사라진 뒤 웨이브 종료 또는 승리 오버레이를 표시한다.
- 사용자 요청에 따라 E2E는 실행하지 않는다.

## 근본 원인

`WaveSystem`은 웨이브 4와 5의 보스를 각각 34초와 40초까지 무조건 기다린다. 일반 적을 일찍 처치해도 다음 예약 항목을 조기에 내보내는 규칙이 없다. 개장수는 생성 후에도 `pathProgress=-70`에서 시작해 본체가 화면에 들어올 때까지 추가 이동 시간이 필요하다.

마지막 적은 논리 시스템에서 피해 프레임에 즉시 제거된다. 같은 프레임에 `GameSession`이 `countdown` 또는 `won`으로 전환하고 `GameScene`이 월드 연출 시계까지 멈추므로, 160ms 사망 연출과 350ms 피해량·간식 연출보다 오버레이가 먼저 나타난다.

## 검토한 방식

### 1. 보스 예약 시각을 마지막 일반 그룹과 같은 시각으로 변경

구현은 단순하지만 일반 적이 남아 있어도 보스가 겹쳐 나오며 웨이브 난도가 의도치 않게 바뀐다. 선택하지 않는다.

### 2. 다음 예약 항목이 보스이고 활성 적이 0명이면 조기 방출

보스의 기존 최종 출현 시각은 유지하면서 플레이어가 일반 적을 빠르게 정리했을 때만 공백을 없앤다. 개장수 본체는 진행도 0에서 시작하고 트럭은 기존처럼 70 뒤에 둔다. 이 방식을 선택한다.

### 3. Scene에서 보스 그래픽만 미리 표시

논리 적과 그래픽의 생성 시각이 달라지고 공격·HP·BGM 상태가 어긋난다. 선택하지 않는다.

웨이브 종료는 고정 350ms 타이머보다 실제 연출 상태를 확인하는 Scene 게이트를 선택한다. 논리 상태는 즉시 전환하되 `EnemyActorPool.dyingCount`, 피해량 풀의 활성 수, `snackFly` 효과가 모두 0이 될 때까지 종료 UI를 보류한다. 보류 중에는 월드 시뮬레이션이 아니라 해당 프레젠테이션 시계만 진행한다.

## 구조

- `WaveSystem`: 다음 spawn이 보스이고 활성 적이 0명이면 예약 시각 전에도 한 번 방출한다. 일반 적과 cap 규칙은 유지한다.
- `EnemySystem`: 개장수의 최소 진행도를 0으로 통일한다. `DogTraderRig`의 트럭 오프셋 -70은 유지한다.
- `balance.ts`와 `EnemyActor`: 개장수 35, 불법번식업자 32.2, 보스 이동 애니메이션 배율 1.4를 사용한다.
- `BossSpawnFeedback`: 보스 종류에만 화면 진동 파라미터를 반환하고 reduced-motion에서는 반환하지 않는다.
- `WaveEndPresentationGate`: countdown 또는 최종 승리 표시 의도를 하나 보관하고 실제 연출이 정리된 뒤 정확히 한 번 반환한다.
- `GameScene`: 보스 actor를 획득한 직후 진동한다. 웨이브 종료 상태에서는 사망·피해량·간식 시각 효과만 계속 진행하고 게이트가 반환한 UI만 표시한다. 패배 흐름은 변경하지 않는다.

## 오류와 경계

- 다음 예약 항목이 일반 적이면 활성 적이 0명이어도 기존 예약 시각을 지킨다.
- 보스 조기 방출은 cursor를 한 번만 증가시키므로 중복 생성하지 않는다.
- countdown과 최종 승리 의도가 중복 등록되면 동일 의도만 허용하고 충돌 의도는 오류로 처리한다.
- 3초 countdown은 논리 전환 시점부터 진행하지만 연출 정리 최대 시간이 더 짧으므로 다음 웨이브가 오버레이보다 먼저 시작하지 않는다.
- 패배 결과의 기존 1200ms 처리와 reduced-motion 접근성 규칙은 유지한다.

## 검증

- `WaveSystem`, `EnemySystem`, 보스 피드백과 웨이브 종료 게이트를 단위 테스트로 red-green 검증한다.
- Scene 배선은 단위 통합 테스트로 고정한다.
- 전체 단위 테스트, 타입 검사와 production build를 실행한다.
- E2E와 시각 스냅샷 테스트는 사용자 요청에 따라 생략한다.
