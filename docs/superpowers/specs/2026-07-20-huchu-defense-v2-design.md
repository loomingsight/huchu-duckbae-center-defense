# 후추덕배 디펜스 V2 게임 설계

- 작성일: 2026-07-20
- 상태: 사용자 변경 통합안 문서화 완료, 사용자 최종 검토 대기
- 대상: 세로형 모바일 우선 웹 게임 V2
- 기반: Phaser 4.1, TypeScript, Vite
- 선행 문서: `2026-07-19-huchu-defense-game-design.md`

이 문서는 V1 구현을 대대적으로 개선하는 V2의 기준 문서다. 화면과 브라우저에 노출하는 게임명은 `후추덕배 디펜스`로 통일하되 저장소명, package name과 기존 배포 URL은 유지한다. 선행 문서와 충돌하는 내용은 이 문서가 우선한다. 충돌하지 않는 WebGL 복구, 에셋 로딩 실패 처리, 결정적 fixed-step, 오브젝트 풀과 브라우저 호환 규칙은 그대로 유지한다.

## 1. 목표

V2는 후추와 덕배의 개성을 살리면서 모바일에서 전투 정보가 즉시 읽히고, 공격이 맞는 순간 시각·움직임·소리가 함께 반응하는 디펜스 게임을 만든다.

핵심 경험은 다음 네 가지다.

1. 사용자는 후추의 이동만 조작하고 덕배가 처음부터 동행하며, 두 강아지의 공격과 습득 기술은 자동 조준·자동 시전한다.
2. 여러 갈래 오솔길에서 보호소에 가장 위험한 적을 우선 방어한다.
3. 간식이 충분해지면 전투를 멈추지 않고 원하는 기술을 직접 습득한다.
4. 모든 피해는 피해 숫자, 피격 반동, 섬광, 이펙트와 효과음이 같은 판정 시점에 맞물린다.

한 판은 5개 웨이브와 약 6~8분으로 구성한다. 계정, 서버, 랭킹, 과금, 영구 성장, 장비와 두 번째 맵은 V2 범위에 포함하지 않는다.

## 2. 화면, 맵과 조작

### 2.1 화면

- 논리 해상도는 `540 × 960` 세로형이다.
- Phaser Scale의 `FIT`과 중앙 정렬을 유지한다.
- 기기 픽셀 비율은 최대 2로 제한한다.
- 맵은 평평한 저채도 녹색 면과 넓고 매끈한 황토색 길을 사용한다.
- 꽃, 잔디 붓 터치, 벤치, 급수대와 울타리 디테일은 V1 목업보다 약 85% 줄인다.
- 관목과 짧은 울타리는 가장자리에만 두고 중앙 전투 공간은 비운다.
- 여섯 진입점과 분기·합류를 포함하는 기존 오솔길 topology는 유지한다.
- 배경의 대비와 채도는 캐릭터, 피해 숫자와 스킬 이펙트보다 낮아야 한다.

### 2.2 보호소

- 보호소는 논리 좌표 `(270, 480)`을 중심으로 배치한다.
- 보호소 최대 HP는 `1,000`이다.
- 웨이브 사이 자동 회복은 없다.
- 보호소 HP는 상단 HUD가 아니라 보호소 바로 아래의 가로 바와 `현재 / 최대` 텍스트로 표시한다.
- HP 상태는 `67% 이상 정상`, `34~66% 경미 손상`, `1~33% 심각 손상`, `0 방어 실패` 네 외형을 사용한다.
- 후추와 덕배는 HP, 피격과 사망이 없고 모든 적 공격은 보호소만 대상으로 한다.

### 2.3 조작

- 데스크톱은 WASD와 방향키, 모바일은 오른쪽 하단 조이스틱으로 후추를 움직인다.
- 조이스틱 표시 링은 390px 폭 화면에서 `92 × 92px`, 실제 hit area는 `112 × 112px`이다.
- 오른쪽 여백은 `max(16px, env(safe-area-inset-right))`, 하단 기술 도크와 간격은 `max(16px, env(safe-area-inset-bottom))`이다.
- 조이스틱 dead zone은 반지름의 15%이며 입력 크기를 이동 속도에 반영한다.
- 후추의 초기 이동 속도는 초당 150 논리 픽셀이다.
- 후추는 맵 경계 안에서 자유롭게 이동하고 적과 물리적으로 서로 막지 않는다.
- 별도 공격 버튼은 없다.

## 3. 아트와 애니메이션 계약

### 3.1 공통 스타일

- 아기자기한 2D 일러스트와 굵고 부드러운 외곽선을 사용한다.
- 명암은 두 단계 이내로 제한하고 배경에는 회화식 붓 질감을 사용하지 않는다.
- 모든 강아지와 사람은 머리 높이와 몸 높이가 `1:1`인 모바일용 비율을 사용한다.
- 적은 실제 인물이 아닌 가상의 풍자 캐릭터로 표현하며 행동, 표정, 옷과 소품으로 잘못된 행동을 읽게 한다.
- 피, 신체 훼손, 사실적 폭력과 비인간화 표현은 사용하지 않는다.

### 3.2 크기

캐릭터 크기는 투명 여백을 포함한 프레임 높이가 아니라 불투명 실루엣 높이로 검증한다. 390px 폭 세로 화면의 목표값은 다음과 같다.

| 대상 | 390px 화면 목표 표시 크기 |
| --- | ---: |
| 후추·덕배 | 48~55px |
| 일반 적 | 58~64px |
| 보스 사람 | 68~75px |
| 개장수 동행 트럭 | 높이 58~66px, 폭 96~110px |
| 보호소 | 68~74px |

이는 승인 전 통합 시안의 약 2/3 크기다. 축소 뒤에도 최종 화면 외곽선은 1.5~2px로 읽혀야 한다.

### 3.3 프레임과 앵커

- 후추, 덕배와 일반 적은 걷기 6프레임과 공격 6프레임을 사용한다.
- 보스는 걷기 6프레임과 공격 8프레임을 사용한다.
- 캐릭터·동작별로 분리된 한 줄짜리 투명 PNG spritesheet와 JSON manifest를 사용한다. 한 프레임은 `256 × 256px`이고 시트 전체 폭은 `frameCount × 256px`다. 서로 다른 캐릭터나 동작을 한 시트에 섞지 않는다.
- manifest는 `key`, `frameCount`, `frameWidth`, `frameHeight`, `fps`, `loop`를 가진다. 공격은 0부터 시작하는 `eventFrame`과 `eventKind(directHit | projectileRelease)`도 필수다.
- 기본 `eventFrame`은 6프레임 공격은 3, 8프레임 공격은 5다. 걷기는 10fps, 6프레임 공격은 12fps, 8프레임 보스 공격은 10fps를 기본으로 하고 예외는 manifest에 명시한다.
- `GameSession`은 `eventFrame / fps`로 계산한 판정 시각을 fixed-step에 맞춰 예약한다. Phaser 애니메이션 callback은 피해를 직접 바꾸지 않고, `directHit`은 이 시각에 판정하며 `projectileRelease`는 이 시각에 투사체만 생성한다.
- 캐릭터 위치는 발 중심 `origin(0.5, 1)`을 기준으로 하고 y좌표로 depth를 정렬한다.
- 한 시트 안 공통 발 앵커 오차는 ±2px, 프레임 중심 이동은 ±3px 이내다.
- 불투명 실루엣은 각 프레임 높이의 75~85%를 차지한다.
- 실제 위치 이동은 서브픽셀을 유지하고 몸통 바운스, 기울기, 귀·꼬리와 공격 반동을 60Hz 트윈으로 보완한다.
- 걷기와 공격 시 신체 잘림, 다른 캐릭터 혼입과 프레임 간 크기 변화가 없어야 한다.
- 꼬리치기는 기본 짖기와 분리된 후추 전용 6프레임 sheet를 사용하고 `fps=12`, `eventFrame=3`, `eventKind=directHit`으로 고정한다. 360도 꼬리 궤적과 원형 먼지 파동은 같은 판정 프레임에 시작한다.
- 개장수와 트럭은 이동 방향을 8개 구간으로 양자화한다. `북, 북서, 서, 남서, 남` 다섯 방향을 제작하고 `북동, 동, 남동`은 대응 방향을 수평 반전한다.
- 방향 전환에는 현재 구간 경계에서 12도 hysteresis를 적용해 굽은 길에서 프레임이 빠르게 왕복하지 않게 한다.
- 개장수는 방향별 걷기 6프레임과 공격 8프레임, 트럭은 방향별 바퀴 회전 4프레임을 사용한다. 각 방향·동작은 별도 sheet와 manifest entry를 갖는다.
- 방향 manifest entry는 `direction`과 선택적 `mirrorOf`를 추가로 가진다. 트럭 frame은 바퀴 지면 접점 사이의 중심을 `origin(0.5, 1)`로 사용하고 방향별 접지 y 오차는 ±2px, 차체 중심 이동은 ±3px 이내다.
- 개장수 공격 manifest는 방향별 `eventSocket`을 필수로 가진다. mirror 방향은 `socketX = frameWidth - sourceSocketX`로 변환해 포획망이 항상 손 위치에서 생성되게 한다.
- 범위 계산의 `H`는 런타임 texture alpha scan이 아니라 Huchu presentation config의 고정 `opaqueHeightLogical=72`를 사용한다. 에셋 검증이 이 값과 실제 렌더 실루엣의 오차를 확인한다.

### 3.4 캐릭터 식별 요소

- 후추: 크림색 털, 흰 주둥이와 가슴, 둥글거나 반쯤 접힌 귀, 진한 눈, 말린 꼬리
- 덕배: 황갈색 긴 털, 흰 가슴, 세워진 술 귀, 풍성한 꼬리, 민트색 옷
- 똥 안 줍는 보호자: 휘파람을 불며 딴청 피우는 40대 남성·여성
- 오프리시 보호자: 빈 목줄을 무심하게 든 60대 남성·여성
- 개장수: 모자를 쓴 60대 남성이 앞에서 걷고, 브랜드 로고가 없는 파란 소형 1톤 트럭이 대각선 뒤를 따라오는 두 파트 실루엣
- 불법번식업자: 과장된 가상 전기충격기를 든 50대 남성·여성

## 4. HUD와 기술 도크

### 4.1 좌상단 자동 기술 HUD

- 기본 짖기는 첫 슬롯에 항상 `짖기 · 자동`으로 표시한다.
- 덕배는 두 번째 슬롯에 처음부터 `덕배 공격 · 자동`으로 표시한다.
- 습득한 반복 기술은 기술명과 남은 쿨타임을 함께 표시한다.
- 아이콘은 이모지나 실사 대신 `currentColor` 기반 단색 SVG를 사용한다.
- HUD는 조작할 수 없는 상태 표시이며 터치 이벤트를 받지 않는다.

### 4.2 하단 간식 기술 도크

- 좌우와 하단 여백은 12px, 전체 높이는 68px이다.
- 간식 보유량 44px 영역과 기술 버튼 세 개를 한 줄로 배치한다.
- 각 기술 버튼은 최소 `88 × 56px` hit area를 확보한다.
- 버튼에는 22px 단색 SVG, 한 줄 기술명과 간식 비용을 표시한다.
- 고정 순서는 `꼬리치기`, `아쿠아빔`, `안전신문고`다.
- 기본 짖기는 간식으로 배우는 기술이 아니므로 하단에 표시하지 않는다.
- 잠긴 버튼은 중립색, 간식이 부족한 버튼은 낮은 대비, 습득한 버튼은 `배움` 상태로 표시한다.
- 간식이 충분한 모든 잠긴 버튼은 금색 테두리와 느린 맥동으로 강조한다.
- 강조는 과하게 깜빡이지 않고 최초 충족 시 `배울 수 있어요` 안내를 약 1.2초만 보여준다.

### 4.3 기타 HUD

- 상단에는 `WAVE n/5`, 경과 시간과 음소거 버튼만 작게 표시한다.
- 모든 적은 캐릭터 바로 위에 작은 한글 이름표, 그 위에 HP 바를 항상 표시한다. 표시명은 `똥 방치 보호자`, `오프리시 보호자`, `개장수`, `불법번식업자`다.
- 이름표는 390px 화면 기준 10px 글자, 1px 어두운 외곽선과 반투명 단색 배경을 사용한다. 피해 숫자는 HP 바보다 위에서 시작한다.
- 이름표와 HP 바는 `EnemyActor` 풀의 일부이며 spawn 때만 문자열을 바꾸고 frame마다 새 객체를 만들지 않는다.
- 보스도 같은 actor 이름표·HP 바만 사용하고 상단에 중복 보스 HP 바를 만들지 않는다. 개장수의 이름표와 HP 바는 사람 파트 위에 붙인다.
- 시작과 재시작 버튼 문구는 `보호소 지키기`다.
- TitleScene 제목, `document.title`, 게임 root의 접근성 라벨과 결과 화면의 게임명은 모두 `후추덕배 디펜스`를 사용한다.

## 5. 기본 짖기와 자동 조준

- 기본 짖기는 처음부터 활성화된다.
- 초기 피해는 18, 공격 간격은 0.8초다.
- 범위는 후추의 현재 불투명 실루엣 높이 `H`를 기준으로 반경 `3H`, 펼침 각도 120도인 부채꼴이다.
- 유효 범위 안의 모든 적에게 같은 판정 시점에 피해를 준다.
- 자동 방향은 범위 안에서 보호소 도달 예상 시간이 가장 짧은 적을 향한다.
- 동률이면 보호소 공격 중인 적, 보스, 후추와 가까운 적, 생성 순서 순으로 결정한다.
- 유효한 적이 없으면 공격 애니메이션과 쿨타임을 소비하지 않는다.
- 공격 애니메이션의 판정 프레임에서 부채꼴 피해, 파동 이펙트, 피해 숫자와 짖기 효과음을 동시에 시작한다.
- 한 번의 부채꼴 공격은 대상 수와 관계없이 짖기 효과음을 한 번만 재생한다.

## 6. 간식과 비차단 기술 습득

- 처치된 적은 간식을 지급하고 보유 간식은 즉시 하단에 반영한다.
- 기술 비용은 기술 종류가 아니라 현재 습득 개수로 결정한다.
- 첫 번째부터 세 번째 습득 비용은 각각 `15`, `25`, `40`이다.
- 잠긴 기술은 어떤 순서로든 선택할 수 있고 현재 다음 비용은 모든 잠긴 버튼에 동일하게 표시한다.
- 보유 간식이 비용 이상이면 모든 잠긴 기술 버튼을 동시에 강조한다.
- 사용자가 버튼을 탭하면 한 트랜잭션에서 비용 검증, 간식 차감과 기술 습득을 처리한다.
- 중복 탭, 이미 배운 기술과 비용 부족 요청은 상태를 바꾸지 않는다.
- 성공하면 전투를 멈추지 않고 약 1초의 `기술명 습득!` toast를 표시하며 좌상단 HUD에 즉시 등록한다.
- 반복 기술은 습득 직후 전체 쿨타임부터 충전을 시작한다.
- 덕배는 기술이 아니라 run 생성 시 함께 배치되는 기본 동료다. 기존 `deokbaeHowl`과 V2 초안의 `덕배 합류`는 구매 목록, `SkillId`, 기술 아이콘과 쿨타임에서 제거한다.
- 기술별 레벨과 반복 강화는 없다. 세 기술을 모두 습득한 뒤의 간식은 결과 점수에만 합산한다.
- 기존 `skillSelection` 모달, 카드 세 장, 학습 일시정지와 재개 카운트다운은 제거한다.

## 7. 자동 기술과 기본 동료

| 기술 | 초기 규칙 |
| --- | --- |
| 꼬리치기 | 쿨타임 8초. 반경은 후추의 불투명 실루엣 높이 기준 `2.2H`이고 360도 안에 활성 적이 하나라도 있으면 자동 시전한다. 모든 대상에게 피해 14와 경로 넉백 35를 적용한다. 일반 적은 1.5초 동안 기존 이동 속도의 60%(`speedMultiplier=0.6`), 보스는 1초 동안 80%(`speedMultiplier=0.8`)로 움직이며 기절은 주지 않는다. |
| 아쿠아빔 | 쿨타임 10초. 현재 HP가 가장 높은 적을 자동 조준하고, 동률이면 보스와 보호소 위협도를 우선한다. 0.6초 동안 표적을 추적하는 빔을 보여준 뒤 한 번에 피해 160을 적용한다. 중간에 표적이 죽으면 남은 충전 시간을 유지한 채 다음 표적으로 한 번만 재지정한다. |
| 안전신문고 | 쿨타임 22초. 시전 시작 시 모든 활성 적을 snapshot하고 0.3초짜리 공용 고지서 비행 timeline을 시작한다. 마지막 판정 step에 아직 살아 있는 snapshot 대상 모두에게 일반 피해 90, 보스 피해 45를 동시에 적용한다. 이미 제거된 대상의 고지서는 마지막 위치에서 사라진다. 각 생존 적의 도장, 피해 숫자와 섬광은 판정과 함께 시작하며 기절은 주지 않는다. |

반복 기술 여러 개가 같은 simulation step에 준비되면 준비 완료 시각, 동률일 때 `꼬리치기 → 아쿠아빔 → 안전신문고` 순으로 고른다. 한 기술을 시전한 뒤 0.2초 후 적 상태를 다시 평가해 다음 기술을 시전한다. 덕배 공격은 이 큐와 독립적으로 진행한다.

- 대상이 없는 준비 기술은 시전과 쿨타임을 소비하지 않고 같은 step에 다음 준비 기술을 평가한다.
- 기술 쿨타임은 실제 시전 시작 시각부터 다시 계산한다. 성공한 시전만 0.2초 전역 기술 큐 잠금을 만든다.
- 아쿠아빔은 충전이 시작되면 쿨타임을 소비한다. 허용된 한 번의 재지정 뒤에도 대상이 없으면 피해 없이 종료한다.
- 꼬리치기 감속은 같은 대상에서 배율을 중첩하지 않고 남은 지속 시간만 더 긴 값으로 갱신한다. 넉백과 감속은 판정 step에 함께 적용되며 ETA는 다음 step부터 감소한 실제 속도로 다시 계산한다.
- 감속은 적별 `moveSpeedMultiplier`와 `slowRemainingMs` 숫자 필드로만 관리한다. 만료가 fixed-step 중간에 오면 감속·정상 두 구간으로 이동량을 나눠 적분하며 ETA도 남은 감속 구간을 포함한다.
- 감속 배율은 일반 이동, 오프리시 돌진 거리와 걷기 animation fps에 적용하지만 공격 준비·공격 cadence에는 적용하지 않는다.
- 짖기와 꼬리치기가 같은 step에 판정되면 gameplay 결과와 각 이펙트·효과음은 모두 유지하되 후추 body 애니메이션은 `꼬리치기 > 아쿠아빔 > 짖기` 우선순위로 하나만 재생한다.

덕배는 모든 run에서 후추의 뒤쪽 안전 offset에 처음부터 등장하고 끝까지 유지된다. 독립적인 1초 공격 시각마다 후추 위치와 기본 짖기의 `3H` 범위·자동 조준 규칙으로 우선 표적을 다시 선택해 단일 대상 피해 11을 준다. 유효 표적이 없으면 공격과 cadence를 소비하지 않으며 HP, 충돌 판정, 습득 비용과 기술 쿨타임은 없다.

## 8. 적과 공격

초기 밸런스는 다음과 같다. 모든 수치와 HUD `displayName`은 단일 enemy config에서 관리하고 플레이테스트는 이 값만 조정한다.

| 적 | HP | 속도 | 보호소 피해 | 공격 간격 | 간식 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 똥 안 줍는 보호자 | 60 | 44 | 25 | 1.8초 | 2 |
| 오프리시 보호자 | 110 | 42 | 50 | 1.8초 | 4 |
| 개장수 보스 | 900 | 25 | 120 | 2.4초 | 20 |
| 불법번식업자 보스 | 1,500 | 23 | 160 | 2.1초 | 35 |

남성과 여성 변형은 같은 계열 안에서 동일한 수치를 사용한다.

### 8.1 똥 안 줍는 보호자

- 짧은 공격 범위에 들어오면 `집기 → 조준 → 투척 → 복귀` 공격 애니메이션을 재생한다.
- 공격 manifest의 `eventFrame`에서 작은 똥 투사체를 짧은 포물선으로 발사한다.
- 보호소에 닿으면 만화식 얼룩, 피해 숫자와 나무 충격음을 표시한다.

### 8.2 오프리시 보호자

- 빈 목줄을 들고 경로를 이동한다.
- 이동 중 4초마다 최대 64 논리 픽셀을 경로를 따라 짧게 돌진한다.
- 보호소에 도달하면 문을 밀치는 큰 동작으로 중간 피해를 준다.
- 추가 강아지 캐릭터나 공격 대상은 생성하지 않는다.

### 8.3 개장수 보스

- 개장수 사람이 gameplay 위치와 HP를 가진 본체고, 트럭은 같은 보스에 종속된 시각 파트다. 별도 적, HP, 충돌, 표적과 사망 이벤트를 만들지 않는다.
- 개장수의 경로 시작점부터 누적한 논리 픽셀 arc length를 `p`, 그 거리를 입력받는 확장 경로 위치 함수를 `P`, 그 위치의 단위 법선을 `N`, 경로별 고정 부호를 `s`라 하면 트럭 기준 위치는 `P(p - 70) + N(p - 70) × s × 28`이다. `p`는 정규화된 0~1 진행률이 아니다. `pathDefinitions`의 `traderSide`는 `P1:-1, P2:+1, P3:-1, P4:+1, P5:-1, P6:+1`로 고정한다.
- 경로 시작 전 70픽셀 구간은 첫 segment를 바깥으로 연장해 사람과 트럭이 함께 화면 밖에서 진입한다. 트럭 pose는 120ms 시각 완충으로 따라가되 simulation 위치와 공격 판정은 바꾸지 않는다.
- 사람과 트럭은 각 pose의 접선으로 방향을 독립 계산하고 8방향 에셋을 선택한다. 공격 준비·공격 중 사람은 보호소 방향을 바라보고 트럭은 마지막 이동 방향을 유지한다. y좌표 depth 정렬과 대각선 offset으로 어느 진입 방향에서도 두 파트가 서로 완전히 가리지 않게 한다.
- 이동 중에는 두 파트가 함께 경로를 따라가고, 공격 준비·공격 중에는 함께 정지한다. 개장수가 중거리에서 포획망을 크게 휘둘러 보호소로 충격파를 보내고, 트럭은 바퀴와 차체의 작은 idle만 재생한다.
- 공격 전 모자와 어깨를 뒤로 젖히는 긴 예비 동작으로 회피 불가능한 보호소 피해를 명확히 예고한다.
- 피격 tint와 반동은 사람과 트럭에 같은 `castId`로 한 번씩 보이지만 피해 숫자, 이름표와 HP 변화는 사람 파트에만 표시한다. 사망 시 두 파트를 같은 actor pool lifecycle로 반환한다.
- 웨이브 4에서 소수의 일반 적 호위와 함께 등장한다.

### 8.4 불법번식업자 보스

- 현실 기기를 그대로 재현하지 않은 과장된 전기충격기에서 전기 파동을 발사한다.
- 바닥의 얇은 예고선과 충전 섬광 뒤 강한 보호소 피해를 준다.
- 웨이브 5에서 혼합 일반 적 증원과 함께 등장한다.

공격 준비 중 새 꼬리치기 판정을 판정 프레임 전에 받으면 일회성 넉백 interrupt로 공격이 취소되고 감속된 이동 상태로 돌아간다. 이는 지속되는 기절 상태가 아니며 이미 적용돼 남은 감속 tick만으로는 공격을 취소하지 않는다. 이미 생성된 투사체와 충격파는 계속 진행한다. 적 공격은 후추와 덕배에게 피해를 주지 않는다.

## 9. 웨이브

| 웨이브 | 생성 시간표 | 목표 소요 | 목적 |
| --- | --- | ---: | --- |
| 1 | `t=0,10,20,30,40초`마다 똥 안 줍는 보호자 2명 | 40~50초 | 이동, 짖기 부채꼴과 첫 기술 습득 안내 |
| 2 | `t=0~45초`, 9초마다 똥 안 줍는 보호자 1명 + 오프리시 보호자 1명, `t=56초` 오프리시 보호자 2명 | 55~65초 | 투사체와 돌진 대응 |
| 3 | `t=0,13,26,39,52,65초`마다 3명. 묶음 순서는 `1+2, 2+1, 1+2, 1+2, 2+1, 1+2` | 65~80초 | 여러 경로 혼합 러시와 세 번째이자 마지막 기술 습득 |
| 4 | `t=0초 2+2`, `20초 1+2`, `40초 1+2`, `68초 개장수 1명` | 80~100초 | 완성된 세 기술과 기본 동료로 첫 보스·호위 적 동시 대응 |
| 5 | `t=0초 2+2`, `20초 1+2`, `40초 1+2`, `80초 불법번식업자 1명`, `110초 2+2` | 100~130초 | 최종 보스와 혼합 증원 |

일반 적 묶음의 `앞 숫자 + 뒤 숫자`는 `똥 안 줍는 보호자 + 오프리시 보호자` 수다. 이 시간표의 총 일반 적과 보스 수는 각각 승인된 구성 총계 `10`, `6+8`, `8+10`, `4+6+1`, `6+8+1`과 일치해야 한다.

- 일반 적 성별 변형은 번갈아 생성한다.
- 웨이브 5 보스의 성별은 run seed로 결정한다.
- 보스는 각 웨이브 일반 적의 첫 공세가 시작된 뒤 등장한다.
- 웨이브별 경로 집합은 각각 `P1~P2`, `P1~P4`, `P1~P6`, `P1~P6`, `P1~P6`다. run seed로 집합을 한 번 섞고 소진할 때마다 다시 섞는다.
- 한 생성 이벤트 안에서는 같은 경로를 중복 사용하지 않는다. 보스도 해당 웨이브의 다음 경로를 사용한다.
- 웨이브는 앞 웨이브 적이 모두 제거된 뒤 3초 안내 후 시작한다.
- 위 목표 소요와 웨이브 사이 안내를 합친 한 판 목표는 6~8분이며, 세 번의 고정 seed 전체 실행 중앙값으로 검증한다.
- 웨이브 5 보스와 남은 적을 모두 처치하면 승리한다.
- 보호소 HP가 0이 되면 즉시 패배 판정을 확정하고 1.2초 실패 연출 뒤 결과 화면으로 이동한다.

## 10. 타격감

모든 적 피해는 별도 `damageApplied` 이벤트로 표현한다. 이벤트는 `castId`, `appliedAtStep`, `targetId`, `amount`, `effectiveAmount`, `position`, `source`, `strength`, `lethal`을 포함한다. `amount`는 방어·보스 보정 뒤 공격 수치이고 `effectiveAmount`는 남은 HP로 제한된 실제 감소량이다. 한 번의 짖기나 광역 기술이 만든 이벤트는 같은 `castId`를 공유한다. 간식 지급용 사망 이벤트와 분리해 중복 지급과 잘못된 후처리를 막는다.

| 강도 | 대표 공격 | 피격 섬광 | 시각 반동 | 피해 숫자 | 카메라 |
| --- | --- | ---: | ---: | ---: | --- |
| 약 | 짖기, 덕배 공격 | 45ms | 2px, scale 1.03 | 13px | 없음 |
| 중 | 꼬리치기, 일반 적 보호소 공격 | 60ms | 3px, scale 1.06 | 17px | 없음 |
| 강 | 아쿠아빔, 안전신문고, 보스 공격 | 90ms | 5px, scale 1.08 | 24px | 45~90ms, intensity 0.0015~0.0035 |

- 피해 숫자는 약공격 크림색, 중공격 주황색, 강공격 노란색을 사용한다.
- 강한 공격일수록 글꼴, 상승 거리와 등장 scale이 커진다.
- 숫자는 적의 머리 위에서 약 350ms 동안 상승하며 같은 적의 120ms 이내 피해는 합산한다. 표시값은 `amount` 합계, 강도는 최댓값, 위치는 마지막 이벤트 위치, 치명 여부는 OR 규칙을 사용한다.
- 피해 숫자 풀은 최대 64개다. 풀 한도에서는 오래된 약공격 숫자부터 회수한다.
- 적 피격은 흰색 tint, 공격 반대 방향의 순수 시각 offset과 squash/recover로 표현한다. 실제 경로 좌표는 꼬리치기 외에는 바꾸지 않는다.
- 전역 hit-stop은 결정적 fixed-step과 다중 공격의 끊김을 피하기 위해 사용하지 않는다. 45~90ms 국소 피격 반응으로 순간 정지감을 만든다.
- 적 HP가 0이면 gameplay 대상에서는 즉시 제거하고, 시각 actor만 160ms 동안 `flash → 1.12배 pop → 축소`한 뒤 풀로 반환한다.
- 간식 아이콘은 사망 위치에서 하단 보유량으로 짧게 날아가 수집 결과를 연결한다.
- 기본 짖기와 덕배 공격에는 화면 흔들림을 사용하지 않는다.
- 안전신문고가 여러 적을 맞혀도 카메라 흔들림과 합성 타격음은 한 번만 발생한다.
- 안전신문고 고지서는 하나의 cast timeline과 공용 이펙트 풀을 사용한다. 대상마다 종이→도장 상태를 바꾸는 notice actor 하나만 할당하고, 모든 도장 판정은 같은 시각이며 적별 타이머를 만들지 않는다.
- 공격음, 강한 합성 타격음과 카메라 흔들림은 `castId`별 한 번만 발생한다. 대상별 피해 숫자, tint와 반동은 각각 유지한다.
- 보호소 피격은 기존 좌우 흔들림, HP 바 붉은 flash, 피해 숫자와 공격 강도에 맞는 카메라 흔들림을 함께 사용한다.

## 11. 오디오

효과음과 BGM은 외부 음원 파일과 새 런타임 의존성 없이 Web Audio API로 합성한다. 음성 연기는 첫 V2 범위에서 제외한다.

### 11.1 효과음 목록

- `barkHuchu`: 낮은 triangle/saw transient와 짧은 band-pass noise를 합친 카툰형 짖기
- `barkDeokbae`: 후추보다 높은 음정과 작은 음량의 짖기
- `hitLight`, `hitHeavy`: noise click과 짧은 저음 sine thump
- `tailSwipe`: 빠르게 회전하는 whoosh와 낮은 pop
- `aquaCharge`, `aquaImpact`: 상승 tone과 filtered noise splash
- `noticePaper`, `noticeStamp`: 짧은 종이 마찰 noise와 낮은 stamp thump
- `shelterWood`: 중저음 wood knock
- `skillLearned`: 세 음의 짧은 상승 chime
- `electricCharge`, `electricImpact`: 제한된 crackle noise와 짧은 저음 impact

### 11.2 BGM

- BGM은 100BPM, 4/4박자, C장조 펜타토닉 기반 32마디로 구성하고 한 loop는 76.8초다.
- 고정 note event table을 사용해 같은 run과 기기에서 멜로디가 달라지지 않게 한다. 칼림바형 짧은 pluck이 주선율, 부드러운 마림바형 저음이 화성, filtered noise shaker가 박자를 담당한다.
- 웨이브 4·5에서 보스가 활성 상태가 되면 다음 박자 경계부터 낮은 tom과 가벼운 shaker accent만 더한다. 보스가 사라지면 다음 박자 경계에서 제거해 기본 아기자기한 분위기로 돌아간다.
- BGM gain 초기값은 28%다. 기본 BGM voice는 최대 6개고 보스 layer를 포함해 이 상한을 넘지 않는다.
- scheduler는 25ms마다 실행하며 앞으로 180ms 구간의 note만 예약한다. 사용이 끝난 oscillator와 gain node는 즉시 disconnect한다.
- `visibilityPause`에서는 `transportPhaseSteps = (AudioContext.currentTime - transportOrigin) / 0.15 mod 512`와 마지막으로 시작한 step을 저장하고 예약된 source를 `stop()`·`disconnect()`한 뒤 suspend한다. 복귀 시 `nextStepIndex = (floor(transportPhaseSteps) + 1) mod 512`, `nextNoteTime = resumedCurrentTime + (1 - fract(transportPhaseSteps)) × 0.15초`로 재구성한다. 정수 경계에서 이미 시작한 step은 다시 예약하지 않으며 숨겨진 동안의 note도 몰아서 재생하지 않는다.
- 승리·패배 확정 시 0.6초 동안 BGM gain을 줄이고 새 run이 시작되면 첫 마디부터 재생한다.

### 11.3 재생 규칙

- `AudioContext`는 TitleScene의 `보호소 지키기` 사용자 입력에서 지연 생성하고 `resume()`한다.
- 시작 전에는 어떤 소리도 자동 재생하지 않는다.
- SFX gain 초기값은 65%다.
- 같은 공격이 여러 대상을 맞혀도 공격음과 강한 타격음은 각각 한 번만 재생한다.
- 안전신문고는 적 수와 무관하게 종이 소리 한 번과 도장 소리 최대 세 번만 재생한다.
- SFX 동시 voice는 최대 12개이며 우선순위는 `보스·보호소 > 강한 기술 > 습득 > 기본 공격`이다. BGM 6개와 합친 AudioContext 전체 상한은 18개다.
- 같은 효과음의 최소 재생 간격과 ±3% pitch variation으로 반복 피로를 줄인다.
- 우측 상단 음소거 버튼은 SFX와 BGM master bus에 즉시 반영하고 선택을 localStorage에 저장한다.
- 탭이 숨겨지면 AudioContext를 suspend하고 명시적 복귀 입력에서 resume한다.
- AudioContext 생성이나 resume이 실패하면 오류 overlay 없이 무음으로 계속 플레이한다.
- 실제 후추·덕배 짖기 녹음이 제공되면 `barkHuchu`, `barkDeokbae`만 파일 기반 버퍼로 대체할 수 있다.

## 12. 소프트웨어 구조

### 12.1 유지하는 구조

- `BootScene`, `PreloadScene`, `TitleScene`, `GameScene`, `ResultScene`
- 결정적 fixed-step과 seeded wave 변형
- 사전 정의 웨이포인트 기반 `PathSystem`
- 적, 투사체와 이펙트 오브젝트 풀
- Phaser를 모르는 순수 규칙 모듈과 렌더링 adapter 분리
- WebGL 고정, lifecycle pause와 context 복구

### 12.2 변경·추가할 경계

- `BarkSystem`: 단일 대상 피해를 120도 부채꼴 다중 대상 판정으로 교체한다.
- `ProgressionSystem`: 임계값과 카드 후보 대신 세 기술의 직접 구매 비용 `15/25/40`, 검증과 원자적 차감을 담당한다.
- `SkillSystem`: 내부 ID와 피해 source를 `scold`에서 `tailSwipe`로 바꾼 꼬리치기, 아쿠아빔, 안전신문고와 0.2초 순차 시전 큐를 담당한다. `deokbaeHowl`은 기술 상태에서 제거한다.
- `CompanionSystem`: run 생성 시 덕배를 기본 초기화하고 follow offset, 기본 짖기와 같은 표적 선택 우선순위, 독립 공격 cadence를 담당한다. 진행·구매 시스템에 의존하지 않는다.
- `EnemyState`: 사용되지 않는 `stunned` 상태와 stun timer를 제거하고 `moveSpeedMultiplier`, `slowRemainingMs`를 snapshot에 포함한다.
- `PathPoseSampler`: `sampleExtended(distancePx)`에서 음수 누적 거리를 첫 segment로 선형 외삽하고 거리 앞뒤 8논리 픽셀의 centered sample로 접선·법선·heading을 결정적으로 계산한다.
- `DogTraderRig`: 개장수와 트럭 두 시각 파트, `P(p - 70) + N(p - 70) × s × 28` follow pose, 8방향 선택과 공유 피격 lifecycle을 담당한다. 120ms frame-rate 독립 exponential damping을 쓰되 spawn 첫 frame, visibility 복귀와 pool 재사용 직후에는 목표 pose로 snap한다.
- `EnemyLabelView`: enemy config의 `displayName`과 actor HP 바를 풀링하고 피해 숫자보다 낮은 화면 layer에 배치한다. 기존 상단 `BossHud`는 제거한다.
- `DamageAppliedEvent`: 모든 적 피해의 시각·오디오 소비 계약이다.
- `ImpactFeedbackSystem`: 피해 강도와 접근성 설정을 섬광, 반동, 숫자와 카메라 반응으로 변환한다.
- `DamageFeedbackPool`: 최대 64개의 Phaser Text와 작은 피격 burst를 재사용한다.
- `AudioSystem`: 지연 생성하는 AudioContext, master bus, visibility 생명주기와 음소거 저장을 담당한다.
- `SfxSystem`: 공유 AudioContext에서 합성 음색, SFX voice cap과 우선순위를 담당한다.
- `BgmSystem`: 100BPM, 512개 16분음표 transport, 32마디 note table, 180ms 선예약과 타악기 보스 layer를 담당한다.
- `HudSystem`: 보호소 아래 HP, 좌상단 텍스트 기술 HUD, 하단 직접 습득 도크와 우측 조이스틱 safe area를 조립한다.
- `AssetVerification`: 꼬리치기를 포함한 4·6·8프레임 시트, 실루엣 점유율, 공통 발 앵커, 중심 이동과 개장수 5방향 원본·3방향 mirror mapping을 검사한다.

V2 `GameMode`는 `playing | countdown | visibilityPause | won | lost`만 사용한다. `skillSelection` 모드, `skillSelectionOpened` 이벤트, 카드 선택 API·모달·재개 카운트다운과 lifecycle·debug bridge·테스트의 전용 분기를 제거한다. 기술 구매는 `playing` 모드에서 step 경계에 소비하는 입력 command이며 world 상태를 전환하지 않는다. 이전 `deokbaeHowl` 기술 정의, 아이콘과 테스트 fixture도 제거하고 덕배 기본 동료 fixture로 대체한다.

한 모듈은 한 책임만 가지며 `GameSession`이 규칙 이벤트를 발생시키고 `GameScene`이 렌더링·오디오 adapter에 전달한다. 오디오와 시각 효과는 simulation 결과를 바꾸지 않는다.

## 13. 데이터 흐름과 우선순위

한 fixed-step의 순서는 다음과 같다.

1. 이동 입력과 기술 구매 command를 한 번 소비하고 후추 위치·습득 상태를 갱신한다.
2. 웨이브를 생성한 뒤 각 적의 step 시작 `slowRemainingMs`로 감속 구간 `min(dt, remaining)`과 정상 구간을 나눠 유효 속도·이동·돌진을 적분하고, 마지막에 감속 남은 시간을 차감한다.
3. 예약된 player impact와 짖기, 덕배, 준비된 자동 기술 하나를 판정한다.
4. 적 피해·꼬리치기 넉백·감속을 반영하고 `damageApplied`를 기록한 뒤 HP 0 적을 제거하고 간식을 한 번만 지급한다.
5. 살아 있는 적의 공격 준비·release와 이미 생성된 보호소 투사체·충격파를 판정하고 `shelterDamaged`를 기록한다.
6. 보호소 HP 0 패배를 판정한다.
7. 최종 웨이브의 활성·대기 적 0 승리를 판정한다.
8. 비최종 웨이브 종료를 판정한다.
9. 다음 기술 시전 가능 시각과 HUD 상태를 갱신한다.

같은 step에 꼬리치기 impact와 적 attack release가 겹치면 3~5번 순서에 따라 꼬리치기 넉백이 먼저 공격을 취소한다. 그보다 앞선 step에 이미 생성된 투사체와 충격파는 계속 판정한다. 결과가 확정된 뒤 들어오는 구매, 피해와 웨이브 요청은 무시한다. 같은 frame의 기술 버튼 입력은 step 경계에서 한 번만 소비한다. 패배와 승리가 같은 step에 성립하면 보호소 파괴에 따른 패배를 우선한다.

개장수 또는 불법번식업자의 활성 boss count가 `0↔1`로 바뀌면 simulation은 상태 이벤트만 낸다. `BgmSystem`은 이 이벤트를 받아 다음 박자 경계에 타악기 보스 layer를 예약하며 gameplay 결과에는 관여하지 않는다.

## 14. 오류 처리와 접근성

- 필수 이미지 로딩 실패와 WebGL 초기화 실패는 기존 재시도·지원 브라우저 안내를 유지한다.
- 실행 중 WebGL context loss는 world를 정지하고 복원 뒤 사용자 확인을 받아 재개한다.
- 브라우저 탭이 숨겨지면 world와 오디오를 자동 정지하고 돌아오면 사용자 입력으로 재개한다.
- 일반 일시정지 버튼은 두지 않는다.
- `prefers-reduced-motion`에서는 카메라 흔들림을 끄고 반동 거리와 pop scale을 절반으로 줄인다.
- 전체 화면 흰색 flash는 사용하지 않고 캐릭터 tint의 최대 지속 시간은 90ms다.
- 음소거 뒤에도 피해 숫자, HP와 시각 피드백만으로 모든 전투 결과를 이해할 수 있어야 한다.
- 기술명은 390px 폭에서 잘림 없이 한 줄로 표시한다.
- 적 이름표는 배경과 WCAG AA 수준의 대비를 확보하고 390px 폭 캡처에서 네 표시명이 잘리거나 HP 바와 겹치지 않아야 한다.

## 15. 성능

- 활성 적 60명, 풀링된 적 이름표 60개, 투사체 80개, 공용 전투 이펙트 120개, 피해 숫자 64개, SFX voice 12개와 BGM voice 6개를 상한으로 한다.
- 자동 조준과 부채꼴 판정은 활성 적 배열과 기존 공간 버킷을 사용한다.
- 안전신문고는 적별 새 타이머를 만들지 않고 하나의 cast timeline에서 적별 비행 경로만 계산한다.
- 개장수 트럭 pose는 기존 경로 sample과 단일 완충 상태만 사용하고 별도 physics body, enemy update와 타이머를 만들지 않는다.
- 개장수·트럭 방향 texture의 예상 GPU 메모리는 합계 24MiB 이내로 유지한다.
- 셰이더, 실시간 blur와 런타임 필터를 추가하지 않는다.
- 최신 데스크톱 Chrome과 WebGL 지원 모바일 Chrome·Safari를 대상으로 한다.
- 프로젝트에 잠긴 Playwright Chromium, 확장 기능 없음, `390 × 844`, device scale factor 2, 4배 CPU throttle과 고정 seed 스트레스 장면을 사용한다. 30초 측정을 세 번 실행해 중앙값 55fps 이상, 50fps 아래 구간이 연속 3초 미만이어야 한다.
- 성능 보고에는 commit, OS, CPU, 브라우저 버전과 전원 상태를 기록한다. 최소 한 대의 실제 모바일 Chrome 또는 Safari에서도 조작·가독성·발열 5분 smoke를 별도로 수행한다.
- 기준 미달 시 장식 파티클과 카메라 효과부터 줄이고 판정, 적 수와 피해 숫자 규칙은 유지한다.

## 16. 테스트 전략

### 16.1 단위 테스트

- 120도, 반경 `3H`, 경계 포함을 갖는 부채꼴 다중 대상 판정
- 보호소 위협도, 보스, 거리와 생성 순서의 결정적 자동 조준
- 비용 `15/25/40`, 세 기술의 자유 습득 순서, 중복 탭과 비용 부족의 원자성
- 학습 중 world, 적, 쿨타임과 애니메이션이 멈추지 않는 규칙
- 꼬리치기 반경 `2.2H` 360도 경계 포함, 피해 14, 넉백 35와 대상 없음 시 준비 유지
- 꼬리치기 일반 적 `speedMultiplier=0.6`·1.5초, 보스 `speedMultiplier=0.8`·1초와 비중첩·긴 지속 시간 갱신
- 판정 전 꼬리치기 넉백의 일회성 공격 준비 취소, 남은 감속만으로는 취소하지 않는 규칙과 이미 발사된 투사체 유지
- `stunned` 상태 제거와 `moveSpeedMultiplier`, `slowRemainingMs` snapshot 계약
- 아쿠아빔 최고 HP 표적, 한 번의 재지정과 단일 최종 피해
- 안전신문고 전체 대상, 일반 90, 보스 45와 기절 부재
- 모든 새 run에서 덕배가 처음부터 존재하고 follow offset, 동일 표적 선택 우선순위, 1초 cadence와 피해 11을 유지하는 규칙
- 구매 가능 `SkillId`, 비용과 쿨타임에 `deokbaeHowl`·`덕배 합류`가 존재하지 않는 규칙
- 0.2초 기술 순차 시전, 매 시전 전 표적 재평가와 덕배 독립성
- 대상 없음 시 기술 skip·준비 유지, 성공 시 쿨타임 시작과 아쿠아빔 재지정 실패 규칙
- `damageApplied`가 피해당 한 번 발생하고 `castId`로 다중 타격을 묶으며 간식 지급 이벤트와 분리되는 규칙
- 피드백 강도 매핑, 120ms 숫자 합산, 숫자·voice pool 상한
- 개장수와 트럭이 gameplay 적 하나, HP 하나와 사망 이벤트 하나만 가지는 규칙
- `PathPoseSampler`의 경로 시작 전 연장, centered tangent, 누적 거리 `-70`, 경로별 `traderSide`, 법선 28 offset과 여섯 경로의 유한 좌표
- 8방향 구간, 12도 hysteresis와 5방향 원본·3방향 mirror mapping
- 감속 만료가 step 중간인 이동·ETA, 돌진 거리·걷기 fps 반영과 공격 cadence 불변
- fake audio clock에서 100BPM 512-step BGM transport, 76.8초 wrap, 최대 polyphony 6과 두 보스 타입 모두에서 동일 boss layer의 박자 경계 전환
- 임의 sub-step에서 visibility pause한 뒤 fractional phase와 다음 미재생 note 순서를 복원하고 중복·누락·몰아 재생이 없는 규칙

- 패배, 승리, 웨이브 종료가 같은 step에 겹칠 때의 우선순위와 단 한 번 전환

## 17. 완료 기준

다음 조건을 모두 만족할 때 V2 구현이 완료된다.

1. `후추덕배 디펜스` 이름과 단순한 세로형 맵, 2/3 크기의 1:1 비율 캐릭터가 모바일에서 명확히 읽힌다.
2. 후추의 짖기가 반경 `3H`, 120도 부채꼴 안 모든 적을 동시에 공격한다.
3. 후추와 영구 동료 덕배가 처음부터 함께 등장하고 하단 기술 도크에서 꼬리치기, 아쿠아빔, 안전신문고 세 기술만 전투를 멈추지 않고 직접 습득한다.
4. 꼬리치기의 360도 넉백·감속, 아쿠아빔과 안전신문고가 합의된 자동 동작을 수행한다.
5. 보호소 HP 1,000이 집 아래에 표시되고 후추와 덕배는 피해를 받지 않는다.
6. 네 적 계열(그중 두 계열은 보스)이 한글 이름표·actor HP 바를 항상 표시하고, 개장수 앞·트럭 대각선 뒤의 방향 대응 2-part 보스와 호위 웨이브가 합의된 외형과 공격을 사용한다.
7. 모든 피해에 강도별 숫자, 섬광과 반동이 나오고 강공격은 제한된 화면 흔들림을 사용한다.
8. Web Audio 합성 효과음, 100BPM 아기자기한 BGM·보스 layer와 음소거가 모바일 자동재생 정책을 지키며 동작한다.
9. 에셋 프레임, 앵커, 실루엣과 성능 상한 검증이 통과한다.
10. 필수 단위·브라우저 테스트와 5웨이브 전체 실행이 통과한다.
