### HD-BL-013 웨이브 종료 오버레이 표시 시점 지연

- 상태: 완료 (2026-07-21)
- 현상: 마지막 적이 쓰러지는 순간 웨이브 종료 오버레이가 먼저 나타나 적의 HP 감소와 사망·퇴장 연출을 가린다.
- 요구사항: 웨이브의 마지막 적 HP가 0이 되고 해당 적을 포함한 모든 몹의 사망 연출과 화면 제거가 끝난 뒤에만 웨이브 종료 오버레이를 표시한다.
- 완료 조건:
  - 웨이브에 남은 모든 적의 HP가 0이 되기 전에는 종료 오버레이가 나타나지 않는다.
  - 마지막 적의 HP가 0이 된 뒤에도 사망 애니메이션, 보상 처리와 화면에서 사라지는 과정이 끝날 때까지 오버레이를 대기시킨다.
  - 활성 적 렌더 액터가 모두 제거되거나 풀로 반환된 다음 프레임부터 종료 오버레이를 표시할 수 있다.
  - 오버레이 대기 중에도 마지막 적의 피해량 표시, HP 바, 사망 애니메이션과 간식 획득 연출이 정상적으로 끝까지 보인다.
  - 대기 시간 동안 다음 웨이브의 적이 먼저 출현하거나 웨이브 종료 처리가 중복 실행되지 않는다.
  - 마지막 웨이브의 승리 오버레이에도 같은 표시 순서를 적용하되 보호소 파괴에 따른 패배 처리는 기존 규칙을 유지한다.
  - 마지막 적 HP 0 → 사망 연출 완료 → 적 제거 → 오버레이 표시 순서를 자동화 테스트로 고정한다.
- 구현 근거: `WaveEndPresentationGate`가 countdown 또는 최종 승리 표시 의도를 보관하고, `GameScene`이 논리 월드는 멈춘 채 사망 actor·피해량 숫자·간식 비행 효과만 계속 진행한다. 세 활성 수가 모두 0이 된 뒤에만 countdown 또는 승리 Result를 정확히 한 번 표시한다. 패배 흐름은 기존 1,200ms 규칙을 유지한다.

### HD-BL-012 보스 출현 대기 제거·등장 화면 진동·이동속도 40% 증가

- 상태: 완료 (2026-07-21)
- 요구사항: 개장수와 불법번식장 운영자가 예정된 출현 시점에 별도 사전 딜레이 없이 즉시 등장하도록 하고, 보스가 생성되는 순간 짧고 분명한 화면 진동을 1회 재생한다. 두 보스의 이동속도는 최초 밸런스 기준보다 총 40% 빠르게 조정한다.
- 완료 조건:
  - 마지막 일반 적을 모두 처치했고 다음 예약 항목이 보스라면 원래 예약 시각이 남아 있어도 다음 시뮬레이션 프레임에 보스를 생성한다.
  - 보스 출현 이벤트가 발생한 시뮬레이션 프레임에 보스가 즉시 생성되어 12시 방향 진입 경로에서 이동을 시작한다.
  - 개장수 본체는 경로 진행도 0에서 바로 보이고 트럭만 진행도 70만큼 뒤에서 자연스럽게 따라온다.
  - 보스 생성 전 별도의 정지, 투명 상태, 예고 연출 대기 또는 추가 타이머가 적용되지 않는다.
  - 개장수와 불법번식장 운영자가 등장할 때마다 화면 전체에 짧은 카메라 진동이 정확히 1회 발생한다.
  - 진동은 모바일 화면에서도 보스 등장을 알아볼 수 있을 만큼 분명하되 조이스틱 입력, 자동 공격, 적 이동과 게임 시간을 멈추지 않는다.
  - 화면 좌표만 흔들고 캐릭터·투사체·공격 범위·충돌 판정의 게임 좌표에는 영향을 주지 않는다.
  - 개장수의 이동속도는 최초 25에서 35로, 불법번식장 운영자는 최초 23에서 32.2로 변경한다.
  - 빨라진 실제 이동과 걷기 애니메이션의 속도가 자연스럽게 맞으며, 개장수와 트럭의 간격·방향도 모든 진입 구간에서 유지된다.
  - 일반 적의 출현 타이밍과 연출, 보스의 12시 방향 등장 규칙, HP·피해량·공격 주기와 공격 패턴은 변경하지 않는다.
  - 보스 이벤트 시각과 실제 생성 시각의 일치, 보스 1개당 진동 1회, 두 보스의 총 40% 속도 적용을 자동화 테스트로 고정한다.
- 구현 근거: `WaveSystem`이 다음 예약 항목이 보스이고 활성 적이 0명이면 예약 시각 전이라도 다음 고정 프레임에 한 번만 방출한다. 개장수 본체는 진행도 0, 트럭은 70 뒤에서 시작한다. 생성 actor를 확보한 프레임에 140ms·0.005 진동을 적용하고 reduced-motion에서는 생략한다. 개장수·불법번식업자 속도를 35·32.2, 이동 애니메이션 배율을 1.4로 맞췄다.

### HD-BL-007 오프리시 보호자 이동 중 순간 소실·도약 수정

- 상태: 완료 (2026-07-21)
- 현상: 오프리시 보호자가 이동 중 잠깐 사라졌다가 진행 방향으로 조금 이동한 위치에서 다시 나타나 순간이동하거나 도약하는 것처럼 보인다.
- 요구사항: 오프리시 보호자의 렌더링과 걷기 애니메이션을 실제 이동 좌표에 연속적으로 연결해 순간 소실과 위치 점프를 제거한다.
- 완료 조건:
  - 정상적인 등장·사망·화면 밖 퇴장 상태를 제외하면 활성 오프리시 보호자가 이동 프레임 사이에 사라지지 않는다.
  - 연속 프레임의 화면 위치가 기존 이동 속도와 경로를 따르며, 한 프레임 이상 건너뛴 것처럼 보이는 위치 점프가 없다.
  - 남성·여성 에셋과 모든 진입 방향에서 걷기 프레임, 좌우 반전, 투명도 및 크기가 끊김 없이 유지된다.
  - 390×844 모바일 화면과 데스크톱 화면에서 동일 현상이 재발하지 않는다.
  - 활성 적 스냅샷과 렌더 액터의 가시성·위치 연속성을 자동화 회귀 테스트로 고정한다.
- 구현 근거: 4초마다 진행도를 64px 즉시 더하던 대시 경계를 제거하고, 동일한 평균 이동량을 초당 16px의 연속 보너스로 분산했다. 감속·ETA도 같은 연속 이동 모델을 사용하며 4초 경계를 통과하는 고정 프레임 회귀 테스트로 위치 점프가 없음을 확인했다.

### HD-BL-008 꼬리치기 동심원 제거 및 마지막 동작 강조

- 상태: 완료 (2026-07-21)
- 요구사항: 꼬리치기 발동 시 나타나는 동심원 형태의 방사형 효과를 제거하고, 후추가 꼬리를 휘두르는 동작을 명확하게 볼 수 있도록 공격 애니메이션의 마지막 프레임을 0.8초간 유지한다.
- 완료 조건:
  - 꼬리치기 시 후추 주변에 동심원, 원형 파동 또는 반복되는 원 테두리 효과가 나타나지 않는다.
  - 꼬리를 가장 크게 휘두른 마지막 프레임이 정확히 800ms 동안 화면에 유지된다.
  - 마지막 프레임 유지가 끝나면 현재 이동 상태에 맞는 걷기 또는 대기 애니메이션으로 자연스럽게 복귀한다.
  - 프레임 유지 중에도 이동 입력, 적 이동, 다른 자동 공격과 게임 시간은 멈추지 않는다.
  - 피해량, 판정 범위, 중앙 바깥 방향 넉백, 둔화 및 쿨다운은 변경하지 않는다.
  - 390×844 모바일 화면에서 꼬리 휘두르기 자세를 분명히 알아볼 수 있고, 효과 제거와 800ms 유지 시간을 자동화 테스트로 고정한다.
- 구현 근거: `CombatEffectPool`과 `GameScene`에서 꼬리치기 원형 호·원형 먼지 생성 경로를 제거했다. 애니메이션 시트의 마지막 프레임 시작 시각에 800ms를 더해 몸동작 종료 시간을 계산하며, 마지막 프레임과 Scene 배선을 단위 테스트로 고정했다.

  - 걷기 애니메이션이 증가한 이동속도와 자연스럽게 맞으며 미끄러지는 것처럼 보이지 않는다.

- 구현 근거: 개장수와 불법번식장 운영자의 속도를 각각 25→30, 23→27.6으로 변경했다. 공용 보스 이동 애니메이션 배율 1.2를 일반 보스 액터와 개장수 사람·트럭 리그에 함께 적용해 이동과 발걸음의 체감을 맞췄다.

### HD-BL-010 기술 습득 직후 첫 쿨타임을 1초로 단축

- 상태: 완료 (2026-07-21)
- 요구사항: 꼬리치기, 아쿠아빔, 안전신문고를 새로 배운 직후에는 첫 자동 시전까지의 쿨타임을 1초로 시작한다.
- 완료 조건:
  - 기술 습득이 확정된 시점의 첫 쿨타임은 정확히 1,000ms이며 습득 즉시 시전되지는 않는다.
  - 유효한 대상이 있으면 습득 후 1초가 지난 첫 시뮬레이션 프레임에 해당 기술이 자동 시전된다.
  - 1초가 지났을 때 대상이 없으면 준비 상태를 유지하고, 이후 대상이 생기는 즉시 기존 자동 조준 규칙으로 시전한다.
  - 첫 시전 이후부터는 HD-BL-011이 최종 확정한 꼬리치기 6초, 아쿠아빔 10초, 안전신문고 19초의 쿨타임을 사용한다.
  - 하단 기술 버튼과 좌상단 자동 기술 HUD가 습득 직후 1초 쿨타임을 일관되게 표시한다.
  - 게임 진행을 멈추지 않는 기존 습득 방식과 간식 비용, 피해량, 범위 및 대상 선정 규칙은 변경하지 않는다.
  - 세 기술 각각에 대해 999ms 이전 미시전, 1,000ms 경계 시전과 이후 정상 쿨타임 복귀를 자동화 테스트로 고정한다.
- 구현 근거: `SkillSystem`이 학습 직후 1,000ms 쿨타임 창을 사용하고, 유효한 대상에 대한 첫 성공 시전 뒤에만 기술별 일반 쿨타임 창으로 전환하도록 변경했다. 대상이 없으면 준비 상태를 유지하며 HUD 진행률도 현재 창을 기준으로 계산한다.

  - 안전신문고의 첫 시전 이후 정상 쿨타임은 기존 22초에서 19초로 변경된다.

  - 세 가지 습득 순서별 안전신문고 비용과 6초·19초 쿨타임 경계를 자동화 테스트로 고정한다.
- 구현 근거: 꼬리치기와 안전신문고의 일반 쿨타임을 6,000ms와 19,000ms로 변경했다. 공용 구매 비용 함수가 안전신문고에만 현재 기본 단계보다 5개를 더하며, 하단 독 표시·구매 가능 판정·구매 큐·실제 차감이 같은 20/30/45 규칙을 사용한다. 정책 전용 신규 테스트는 추가하지 않고 기존 회귀 기대값만 갱신했다.
